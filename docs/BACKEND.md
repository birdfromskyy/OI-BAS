# Backend и запуск в Docker

Контур состоит из трёх постоянных контейнеров:

- `db` — PostgreSQL 16 с именованным томом `postgres_data`;
- `api` — Go + Gin, выполняет миграции при старте;
- `web` — собирает SvelteKit PWA и раздаёт её через Caddy. Запросы `/api/*`
  и `/healthz` Caddy передаёт в `api`, поэтому браузер работает с одним origin.

## Первый запуск

```sh
docker compose --env-file .env -f compose.dev.yaml up -d --build
docker compose --env-file .env -f compose.dev.yaml run --rm api bootstrap "ФИО первого администратора"
```

Вторая команда выведет единственную персональную ссылку администратора. Её
нужно сохранить: в базе хранится только SHA-256 хеш токена. Открывать
приложение следует по этой ссылке. Администратор затем создаёт сотрудников в
разделе «Штат»; после создания, а также при перевыпуске, ссылка показывается
в системном диалоге для копирования.

В development приложение доступно на `http://localhost:8080`, API — на
`http://localhost:8081`, а PostgreSQL — на `localhost:5435`. При production
развёртывании используйте отдельный compose-файл. До запуска задайте
`APP_BASE_URL_PROD`, иначе новые ссылки будут содержать localhost:

```sh
APP_BASE_URL_PROD=https://ekipazh.example.ru \
  docker compose --env-file .env -f compose.prod.yaml up -d --build
```

## Модель доступа и синхронизации

Паролей и регистрации нет. Каждая действующая ссылка содержит 256-битный
случайный токен. В браузере он сохраняется в localStorage, а затем передаётся
в API как `Authorization: Bearer`. Перевыпуск заменяет токен, отзыв делает
ссылку неработающей. На пользователя одновременно действует только один
токен.

PWA хранит рабочую копию и очередь операций локально. Кэш данных изолирован
по персональной ссылке, а каждая посылка очереди помечена ID сотрудника. До
подтверждённого профиля синхронизация не начинается — другая ссылка на том же
телефоне не сможет отправить чужие записи. Без сети приложение остаётся
открытым с сохранённым профилем и данными; при появлении связи API сначала
проверяет, что ссылка всё ещё действует.

У каждой синхронизируемой записи есть `revision`. Создание использует ревизию
`0`, а изменение или мягкое удаление обязано принести последнюю ревизию с
сервера. Несовпадение даёт `409`: локальная посылка остаётся в очереди, экран
подгружает серверную версию, а осознанная новая правка заменяет конфликтную
посылку. Повтор одного operation ID возвращает исходную ревизию, поэтому
потерянный HTTP-ответ не создаёт ложный конфликт.

Роли — `владелец`, `администратор`, `пилот`, `наблюдатель`; сервер повторно
проверяет их на каждом запросе, интерфейсный список ролей не является защитой.
Владелец единственный назначает и снимает роль администратора, а также меняет
его ссылку и состояние доступа. Передача владения выполняется отдельной
операцией. Администратор и владелец ведут все записи. Пилот читает весь журнал,
создаёт полёт только на себя и может менять или удалить любой полёт со статусом
ровно `запланирован`; завершённые записи для него закрыты. Пилот создаёт и
правит БВС, но удалить БВС не может; чеклисты и аккумуляторы ему доступны по
CRUD. Наблюдатель читает все эти разделы без изменений.

Схема БД гибридная: исходный JSONB `data` сохранён для совместимости и
расширяемых полей, а ключевые поля вынесены в типизированные колонки
PostgreSQL — ID БВС/пилота/чеклиста/площадки, статус, даты, числовые показатели
и ревизии. Внешние ключи защищают новые записи. Удаление БВС, чеклиста,
площадки и полёта мягкое; оно запрещено, пока запись нужна другому сохранённому
документу. Так исторические данные остаются читаемыми и не получают ссылки на
логически удалённую сущность. Для одного БВС сервер допускает максимум три
активных чеклиста, включая одновременные офлайн-синхронизации.

## Проверки

```sh
(cd frontend && npm run lint && npm run check && npm run test && npm run build)
(cd backend && go test ./... && go vet ./...)
```

Полный интеграционный тест API использует отдельную временную схему в
PostgreSQL и после выполнения её удаляет:

```sh
set -a && source .env && set +a
TEST_DATABASE_URL="postgres://${POSTGRES_USER}:${POSTGRES_PASSWORD}@localhost:${POSTGRES_PORT}/${POSTGRES_DB}?sslmode=disable" \
  go test ./internal/httpapi -run TestAPIIntegration -v
```
